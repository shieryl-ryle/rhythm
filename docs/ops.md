> **Scope:** keep the deployed app running and give a clear recovery path. Architecture lives in

## Deploy
| Environment | URL | How to deploy | Who can deploy |
|---|---|---|---|
| Web demo (judges) | `https://<firebase-project-id>.web.app` (TBD once the project exists) | `cd app && flutter build web --release && firebase deploy --only hosting` | Team members with the Firebase Hosting Admin role |
| Android APK (judges, testers) | Shared download link (TBD: GitHub release or Drive) | `cd app && flutter build apk --release` → upload `build/app/outputs/flutter-apk/app-release.apk` | Plan owner |

**Deploy checklist:** tests green → build → deploy → open the public URL in a clean browser →
TC-040 (happy path) → note the version in the release log ([Release](release.md) §6).

**Demo builds** add `--dart-define=DEMO=true` (enables the "Load demo data" button, labelled
synthetic; see [seed](../seed/README.md)). The judged web build is a demo build.

## Configuration & secrets
No server secrets exist in P0. The Gemini key is held by Firebase AI Logic, not by the app or the
repo. Local files listed below are git-ignored. **Never commit values.**

| Name | Where | Purpose |
|---|---|---|
| `app/lib/firebase_options.dart` | repo (public identifiers only) | Firebase project config generated by FlutterFire CLI |
| Gemini Developer API key | Firebase console (AI Logic) | Used by the Firebase proxy only |
| `FIREBASE_APPCHECK_DEBUG_TOKEN` | local dev only | App Check debug provider for emulators and local web |
| `RECAPTCHA_SITE_KEY` | `--dart-define` at web build | App Check web provider (public key) |
| `app/android/key.properties` | local only, git-ignored | Android release keystore path and passwords |
| `upload-keystore.jks` | password manager, **backed up**, outside the repo | APK signing key |

**Identity & permissions (least privilege):**
| Identity | Roles (exact, never owner/editor/admin) | Why |
|---|---|---|
| Deploying team member | Firebase Hosting Admin (verify the role name in IAM) | Deploy the web build only |
| Plan owner | Project owner of the Firebase project (only one person) | Billing, AI Logic setup, App Check |

**Rotation:** regenerate the Gemini key in the console → update AI Logic → no app redeploy
needed. If a secret ever lands in git history, rotate immediately; deleting the commit is not
enough.

## Observability
- **Logs:** there is no server. The Firebase console shows AI Logic request counts and errors. The
  app logs AI calls on-device in debug builds only, with purpose, model, latency, and ok/error.
  **Never** prompt content (BR-020).
- **Health check:** static hosting, so the check is TC-040 (load the URL, reach Today). It costs
  nothing and calls no paid API.
- **AI calls:** monitor AI Logic usage and errors in the Firebase console.

**Signals that matter:**
| Signal | Source | Healthy |
|---|---|---|
| AI error / timeout rate | Firebase AI Logic dashboard | < 10% [assumption]; fallbacks keep the app working either way |
| AI requests per day | Firebase AI Logic dashboard | Within EQ-006 × number of testers |
| Web demo loads | TC-040 | Passes |

## Runbook — common incidents
| Symptom | Likely cause | Fix |
|---|---|---|
| Options never AI-worded | AI off, App Check rejecting, quota hit, or model retired | Check AI Logic dashboard; App Check debug token for dev; confirm the model ID in Methods. The app still works on library text |
| AI Logic 403 from web | App Check web provider misconfigured or domain not allowed | Fix the reCAPTCHA key and allowed domains; redeploy |
| Web build shows a blank page / DB error | drift web assets (`sqlite3.wasm`, worker) missing from `web/` | Re-add per the drift web guide; rebuild |
| Deploy fails with a permission error | Deployer lacks the Hosting role | Grant the specific role; never Owner |
| Notifications not firing on Android | Permission denied, battery optimisation, exact alarms not granted | Check [Mobile QA](mobile-qa.md) permissions; reminders are inexact by design |

## Backup & recovery
- **User data:** on the device only. The export file is the only backup (BR-017). There is
  nothing to restore on a server.
- **Web demo:** stateless static hosting; redeploy from `main`. Firebase Hosting keeps previous
  releases and can roll back from the console.
- **Signing key:** back up `upload-keystore.jks` in the password manager; losing it means a new
  APK identity.

## If the project outlives the event
- Legal and ethics review (ADR-004); expert review of DS-002 and DS-003.
- Paid Gemini tier permanently; budget alerts; model-retirement watch.
- Encryption at rest for the local DB; a privacy policy URL; store compliance via
  `/ship-mobile-release`.
- P1 circles: accounts, Firestore security rules, account deletion, moderation.
